# Smilo – AI-Powered Dental Disease Detection System
## Complete User Flow and Application Structure

The Smilo AI-Powered Dental Disease Detection System is a comprehensive web-based healthcare platform that begins when a user lands on the Home Page featuring a hero section with the tagline "AI-Powered Dental Disease Detection" alongside visual elements showcasing the technology, followed by sections explaining "How It Works" (describing the three-step process of upload, AI analysis, and report generation), "Why Choose Smilo" (highlighting accuracy, speed, convenience, and AI-powered insights), a Features section displaying key capabilities like instant analysis, detailed reports, and doctor consultations, a visual representation of the Doctors network, a call-to-action section encouraging users to try the service, and a footer with links and contact information, all connected through a persistent animated Navbar that remains fixed at the top across all pages containing links to Home, How It Works, Detect Disease, Doctors, About, Contact, and a dynamic Login/Dashboard button that changes based on authentication status, where the entire application is built on a React TypeScript frontend using Vite as the build tool, Tailwind CSS for styling, Shadcn UI for component library, React Router DOM for navigation, Framer Motion for animations, and React Hook Form with Zod for form validation and schema management, with the frontend communicating with a backend API service built using Node.js/Express or FastAPI that handles authentication using JWT tokens stored in httpOnly cookies or localStorage, manages user sessions, validates requests, and interfaces with a PostgreSQL or MongoDB database for storing user accounts (containing fields like userId, name, email, hashedPassword, role enum of 'user' or 'doctor', phoneNumber, city, profilePicture, createdAt, updatedAt), upload records (uploadId, userId, xrayImageUrl, uploadedAt, status enum of 'pending', 'processing', 'completed', 'failed'), analysis results (resultId, uploadId, userId, prediction enum of 'Healthy' or 'Dental Caries', confidenceScore, heatmapImageUrl, severityLevel enum of 'None', 'Mild', 'Moderate', 'Severe', aiModelVersion, processedAt, precautions array, dietGuidance array, oralCareGuidance array), doctor profiles (doctorId, userId, specialization, experience, clinicName, clinicAddress, city, availability, verified boolean, rating), and patient-doctor consultations (consultationId, patientId, doctorId, resultId, notes, consultationDate, status), while the AI processing pipeline consists of a separate microservice or Lambda function that receives uploaded OPG X-ray images through a presigned S3 URL or direct file upload endpoint, validates the image format and quality, preprocesses the image using OpenCV or PIL for resizing to model input dimensions (typically 224x224 or 512x512), normalization, and augmentation if needed, feeds the preprocessed image into a pre-trained deep learning model built using TensorFlow or PyTorch (either a custom CNN architecture, ResNet, VGG, EfficientNet, or DenseNet fine-tuned on a labeled dental X-ray dataset containing healthy teeth and caries-affected teeth images), generates predictions with softmax output providing confidence scores for each class, creates a Grad-CAM or saliency map visualization showing which regions of the X-ray influenced the AI's decision by highlighting areas of concern in a heatmap overlay, packages the prediction results including class label, confidence percentage, severity assessment based on confidence thresholds and affected area size, and returns this data to the backend API which stores it in the database and updates the upload record status, implementing the complete user authentication flow where unauthenticated users browsing the Home Page can click on navigation links freely except when they click "Detect Disease" or the "Upload X-ray" call-to-action button which triggers a route guard that redirects them to the Login/Register page at route "/auth" rendering the Auth.tsx component featuring a tabbed interface or toggle between Login and Register forms where the Register form collects name, email, password, confirm password, phone number, city selection dropdown, and role selection (defaulting to 'user' with an option for 'doctor' that shows additional fields like specialization, clinic details, and verification documents upload), validates inputs using Zod schemas ensuring email format, password strength (minimum 8 characters, one uppercase, one number, one special character), phone number format, and matching password confirmation, submits the registration data to POST /api/auth/register endpoint which hashes the password using bcrypt, creates a new user record in the database with verified status false for doctors requiring admin approval, sends a verification email, and returns a success message prompting the user to log in, while the Login form accepts email and password, validates credentials against POST /api/auth/login endpoint which queries the database for matching email, compares hashed passwords, generates a JWT token containing userId, email, and role if authentication succeeds, returns the token along with user profile data, stores the token in localStorage or httpOnly cookie, updates the application auth context using React Context API or state management like Zustand, and redirects authenticated users based on their role where regular users are taken to "/dashboard" route rendering the Dashboard.tsx component displaying a personalized User Dashboard with a welcome message using their name, profile section showing avatar and account information with edit capability, a statistics card showing total uploads count, reports generated count, and consultations count, an upload history section displaying a table or card grid of previous X-ray uploads with columns for upload date, thumbnail preview, status badge (pending/processing/completed/failed), view report button for completed analyses, and delete option, a quick actions section with prominent buttons for "Upload New X-ray" and "View All Reports", recent activity feed showing latest interactions, upcoming appointments if any consultations are scheduled, and navigation cards linking to Doctors, Profile Settings, and Help Center, while doctors logging in are redirected to "/doctor-dashboard" route rendering a specialized Doctor Dashboard showing their profile with verification badge, statistics including total patients reviewed, pending reports, consultation requests, average rating, a pending reports section listing patient cases assigned to them or within their city requiring review with patient name (anonymized or full based on privacy settings), upload date, AI preliminary diagnosis, view details button, a reviewed cases history with filters by date and diagnosis type, a schedule section showing upcoming consultation appointments, and settings for availability status and notification preferences, implementing the complete X-ray upload and analysis flow where authenticated users clicking "Upload New X-ray" or "Detect Disease" from the Navbar are navigated to "/upload" route rendering the Upload.tsx page component featuring a prominent drag-and-drop zone or file input specifically accepting image files (JPEG, PNG) with validation checking file size limit (maximum 10MB), image dimensions (minimum 500x500 pixels), and file type, displaying an instant preview of the selected X-ray image with zoom and rotate controls for user verification, showing a checklist of requirements (OPG/Panoramic X-ray, clear visibility, no personal information visible), collecting optional metadata like patient age bracket and symptoms through a form, displaying terms acknowledgment checkbox stating that this is for screening purposes only and not a replacement for professional diagnosis, featuring a prominent "Analyze X-ray" button that when clicked triggers a loading state with animation and progress messages ("Uploading image...", "Processing with AI...", "Generating report..."), uploads the image to the backend via POST /api/uploads endpoint which saves the file to cloud storage (AWS S3, Google Cloud Storage, or Cloudinary), creates an upload record in the database with status 'processing', returns an uploadId, triggers an asynchronous job or webhook to the AI service passing the image URL and uploadId, where the AI service downloads the image, runs inference through the deep learning model taking 5-15 seconds depending on model complexity and server resources, generates the prediction with confidence score (e.g., "Dental Caries detected with 87.3% confidence"), creates a heatmap visualization highlighting affected tooth regions or cavities in red/orange overlay on the original X-ray, determines severity level based on confidence score thresholds (Mild: 60-75%, Moderate: 75-90%, Severe: 90-100%) and affected area percentage, packages comprehensive analysis results including prediction class, confidence score, severity level, affected regions coordinates, heatmap image URL, and relevant medical guidance arrays, sends results back to the backend API via POST /api/results endpoint or callback webhook which stores the complete analysis in the results table linked to the uploadId and userId, updates the upload record status to 'completed', triggers a notification to the user via email or in-app notification, and optionally assigns the case to nearby verified doctors in the user's city for professional review, after which the user is automatically redirected to "/results/:resultId" route rendering the Results.tsx page component that fetches and displays the comprehensive analysis report featuring a header section with result timestamp and download PDF button, a visual comparison section showing the original X-ray image side-by-side with the AI-generated heatmap overlay highlighting areas of concern with color-coded intensity, a diagnosis card prominently displaying the prediction result ("Healthy Teeth" with green check icon or "Dental Caries Detected" with warning icon), the confidence score displayed as a percentage with a circular progress indicator, and the severity level badge (None/Mild/Moderate/Severe) with appropriate color coding, followed by a detailed findings section explaining what the AI detected in layman's terms such as "The AI model has identified potential cavity formation in the upper right molar region" with technical details available in an expandable accordion, a precautions section listing immediate steps the user should take including scheduling a dental appointment, avoiding extremely hot or cold foods, maintaining gentle brushing around affected areas, and using fluoride toothpaste, a dietary guidance section with recommendations like reducing sugar intake, avoiding sticky candies and carbonated drinks, increasing calcium-rich foods like milk and cheese, drinking water after meals, consuming crunchy vegetables for natural cleaning, and limiting acidic foods, an oral care guidance section with best practices including brushing twice daily with proper technique demonstration video or animation, flossing daily especially around affected areas, using antiseptic mouthwash, scheduling regular dental checkups every 6 months, and considering fluoride treatments, a "Consult a Doctor" prominent section encouraging users to get professional verification featuring a button "Find Dentists Near You" that navigates to the Doctors page with results pre-filtered by the user's city, and action buttons for saving the report to their dashboard history (automatically done), downloading a PDF version for physical dental visit, sharing with a doctor through the platform, and uploading another X-ray, implementing the comprehensive Doctors page accessible via "/doctors" route rendering the Doctors.tsx component that displays a hero section explaining the verified dentist network, a search and filter bar allowing users to filter by city (defaulting to user's registered city), specialization (General Dentistry, Orthodontics, Periodontics, Endodontics, Oral Surgery), rating (minimum stars), availability (available today, available this week), and consultation type (in-clinic, online video consultation), followed by a grid or list of doctor cards each displaying the doctor's profile picture, name with verification badge icon, specialization, years of experience, clinic name and address, city location, average rating displayed as stars with review count, availability status with next available slot timing, languages spoken, consultation fee, a "View Profile" button that opens a modal or navigates to "/doctors/:doctorId" showing detailed information including biography, education credentials, certifications, patient reviews with ratings and comments, photo gallery of clinic, accepted insurance, and consultation hours, and action buttons for "Book Consultation" that allows users to select appointment date and time, attach their X-ray report from history, add notes about their symptoms, and confirm booking which creates a consultation request in the database sent to the doctor for approval, with future enhancement noting that a "Map View" toggle will integrate Google Maps API or Mapbox displaying doctors as pins on an interactive map clustered by proximity allowing users to visualize nearest options and get directions, implementing the complete Doctor Panel functionality where users registering with role 'doctor' and providing verification documents go through an admin approval process updating their verified status to true, after which they can log in and access "/doctor-dashboard" route with a specialized interface showing their profile management section where they can update clinic information, availability schedule with time slots, consultation fees, and upload clinic photos, a patient reports section displaying a table of cases assigned to them or available for review in their city filtered by status (pending review, reviewed, consultation requested) with columns for patient ID or name, upload date, AI preliminary diagnosis, severity level, and action buttons, clicking "View Report" on any case opens a detailed modal or navigates to "/doctor/reports/:resultId" rendering a comprehensive view showing the patient's X-ray images with original and AI heatmap side-by-side, AI prediction with confidence score and severity assessment, patient metadata like age bracket and reported symptoms, analysis timestamp and model version used, an "Add Professional Notes" section with a rich text editor where the doctor can input their professional opinion including confirming or correcting the AI diagnosis, providing detailed explanation of findings, recommending specific treatments like filling, root canal, extraction, or monitoring, prescribing medications if applicable, and scheduling follow-up timeline, buttons to "Validate AI Prediction" or "Flag Incorrect Prediction" which helps improve the model through feedback loop, and options to "Approve Consultation Request" if the patient requested to book an appointment changing consultation status to 'confirmed' and notifying the patient, with all doctor notes and validations stored in the consultations table linked to the specific result and patient, accessible to the patient through their dashboard where they can view doctor feedback on their reports, implementing comprehensive route protection and navigation
